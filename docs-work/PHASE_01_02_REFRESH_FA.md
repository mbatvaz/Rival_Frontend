# بازبینی و به‌روزرسانی فازهای ۱ و ۲ — ۱۴ نوامبر ۲۰۲۶

این کار با درخواست مستقیم مالک برای بازبینی دو فاز پذیرفته‌شده بر اساس زیرساخت جدید انجام شد. محدوده شامل پایهٔ استاتیک، پوسته و ناوبری، صفحات عمومی، ورود و حرکت‌های مرتبط است. پذیرش تاریخی این دو فاز حفظ می‌شود؛ اصلاحات این نوبت آمادهٔ بازبینی مالک هستند. فاز ۳ فقط برای مصرف‌کنندگان اجزای مشترک آزمون رگرسیون می‌شود؛ پذیرش آن یا شروع فاز ۴ نتیجهٔ این کار نیست.

## نتیجهٔ فاز ۱

- ساخت استاتیک، ۷۳ context، فهرست مرکزی و alias، basePath، مرز دادهٔ آزمایشی، ثبت‌گر lazy، کپی fixture، ۹ خانوادهٔ توکن، سه وزن فونت و ۷۱ SVG بررسی شدند. نیازی به بازسازی این اجزا نبود.
- اعتبارسنجی لینک‌ها و ساختار مهارت‌ها به `npm run lint` متصل شد؛ فرمان مستقل `npm run lint:docs` و Task با نام «Rival: Documentation + Skill Checks» اضافه شد.
- ماژول مشترک حرکت، زمان و easing را از CSS تولیدشده از توکن‌های اصلی می‌خواند. فایل‌های طراحی، بسته‌ها و وابستگی‌های npm تغییر نکرده‌اند.
- خروجی همچنان ۲۱ قالب محصول و ۵۲ placeholder دارد. صفحات مراحل بعد برای اجرای دوبارهٔ فاز ۱ حذف یا به حالت قدیمی بازگردانده نشدند.

## نتیجهٔ فاز ۲

- ورود صفحه‌ها، خروج مسیر و باز/بسته‌شدن برگه‌ها به زمان‌های مصوب متصل شدند. خروج مسیر ۱۴۰ms، ورود صفحه و برگه ۳۸۰ms، خروج برگه ۲۴۰ms و محوشدن پرده ۱۴۰/۲۴۰ms است.
- برگه‌های موبایل و تأییدها از پایین حرکت می‌کنند. PortfolioViewer دسکتاپ، مطابق جایگاه مرکزی تأییدشده، fade/scale کوتاه دارد؛ مدیریت فوکوس، زمینهٔ inert و بازگرداندن اسکرول همچنان متعلق به ماژول Sheet است.
- اسلایدر خانه با کلیدهای جهت، Home/End، نشانگرهای دارای نام و کشیدن تصویر کنترل می‌شود. دکمهٔ توقف/ادامهٔ صریح دارد. خودکاربودن هنگام فوکوس، hover، مخفی‌شدن سند، inert بودن زمینه یا کاهش حرکت متوقف می‌شود. اعلان صفحه‌خوان برای انتخاب دستی فعال است و تغییر خودکار اعلام پیاپی ایجاد نمی‌کند.
- نشانگرهای کوچک داخل دکمه‌های حداقل ۴۴×۴۴ قرار دارند؛ کنترل‌های پیکانی حذف‌شدهٔ قبلی بازگردانده نشدند. کنترل‌ها داخل بخش موجود توضیح اسلایدر هستند؛ گرید، عکس‌ها و ترکیب تأییدشدهٔ دسکتاپ حفظ شدند.
- حرکت سه قدم رزرو هنگام ورود به دید فقط یک‌بار، به مدت ۶×توکن ۷۰۰ms اجرا می‌شود؛ سپس در حالت نهایی می‌ماند. نبود IntersectionObserver یا کاهش حرکت، نسخهٔ ثابت و خوانا می‌دهد.
- بارگیری نمونه‌کارها به shimmer مبتنی بر transform تبدیل شد؛ زمان چرخه ۲×توکن ۷۰۰ms است. آیکون انتظار ورود از توکن ۷۰۰ms استفاده می‌کند. کاهش حرکت هر دو را ثابت می‌کند.
- در بازبینی تصویری پوستهٔ مشتری، دکمهٔ رزرو سبز بود. منبع Design System v2 آن را جوهری تعریف می‌کند؛ رنگ به bg-inverse و نام دسترس‌پذیر به «رزرو نوبت» اصلاح شد. بازخورد فشردن ناوبری از حرکت کوتاه موجود در زبان دکمه‌ها استفاده می‌کند.

## رفتار fallback و قطع حرکت

آزمون حذف APIهای حرکت و مشاهدهٔ تقاطع، خطای `InvalidStateError: ViewTransition opt-in disabled` را در گذار بومی بین دو سند آشکار کرد. مسیر حرکت به ورود CSS و خروج Web Animations یکپارچه شد؛ opt-in گذار بین سندها حذف شد. این تصمیم از ایجاد دو مسیر رقیب جلوگیری می‌کند و ناوبری عادی را در نبود API حفظ می‌کند. خطاهای سراسری فیلتر یا مخفی نشدند. ردشدن ready در گذار ناموفق در [مستند MDN](https://developer.mozilla.org/en-US/docs/Web/API/ViewTransition/ready) نیز توضیح داده شده است.

تغییر زندهٔ کاهش حرکت، انیمیشن JS را لغو می‌کند و کار اصلی ادامه می‌یابد. نبود getAnimations، بستن برگه را مسدود نمی‌کند. فشار تکراری Escape، بستن و بازکردن دوباره و بازگشت فوکوس آزموده می‌شوند. هیچ زمان‌سنج انتظار برای حرکت در مسیر کاربر اضافه نشده است.

## آزمون‌ها و شواهد

نتیجهٔ نهایی پس از آخرین اصلاح کد:

- `npm.cmd run build`: موفق؛ ساخت‌های داخل test runner نیز موفق بودند.
- `npm.cmd run lint`: structure، ESLint، Stylelint و lint:docs اجرا شدند. لینک‌ها و ساختار مهارت‌ها با validator محلی بررسی می‌شوند؛ این ابزار جایگزین parser کامل YAML یا ارزیابی رفتاری مهارت نیست.
- `npm.cmd test`: **۸۷ آزمون موفق**، حدود یک دقیقه؛ شامل ۷۶ آزمون پیشین و ۱۱ سناریوی تازه.
- `npm.cmd run test:subpath`: **۸۷ آزمون موفق**، حدود ۱٫۱ دقیقه؛ خروجی پس از آزمون به basePath ریشه بازسازی شد.
- اجرای هدفمند نهایی اسلایدر/عرض‌های مرزی/responsive-a11y پیش از اصلاح مستقل رنگ دکمه: ۱۷ آزمون موفق؛ اجرای کامل ۸۷ آزمونی پس از اصلاح رنگ همهٔ آن‌ها را نیز پوشش داد.
- تصاویر شش منبع پیش‌فرض بازتولید شدند؛ مقایسهٔ دستی شش صفحهٔ موبایل، نمونه‌های تبلت/دسکتاپ و جزئیات اسلایدر انجام شد. آزمون‌ها علاوه بر screenshot، تعامل، route، axe و keyboard را بررسی کردند؛ تطابق کامل پیکسلی همهٔ حالت‌ها ادعا نمی‌شود.
- SHA-256 تمام ۱۲۷۱ فایل طراحی با فهرست پیش از کار مقایسه شد: **صفر فایل اصلی تغییر کرد**. فایل قفل وابستگی و مرجع‌های اصلی تغییر نکردند. `git diff --check` بدون خطا بود.

در اجرای اولیه، دو locator آزمون به پیوندی اشاره می‌کردند که در ترکیب دسکتاپ عمداً پنهان است؛ آزمون به پیوند واقعی caption متصل شد. سپس آزمون نبود API خطای گذار بین سندها را نشان داد؛ اصلاح مسیر حرکت این خطا را برطرف کرد. فقط نتایج اجرای نهایی در بالا به‌عنوان نتیجهٔ تحویل گزارش می‌شوند.

- آزمون‌های جدید: انتخاب صفحه‌کلید/نشانگر، توقف و ادامه، hover/focus، کاهش حرکت زنده، اجرای یک‌بارهٔ مراحل، بازگشت فوکوس/قطع برگه، نبود API، shimmer و ۲۱ ترکیب صفحه/عرض در ۳۷۵، ۷۶۷، ۷۶۹، ۱۰۲۳، ۱۰۲۴، ۱۰۲۵ و ۱۴۴۰.
- تست‌های قبلی: axe/keyboard/route در ۳۹۰، ۷۶۸ و ۱۲۸۰، کوچک‌ترین عرض ۳۲۰، عرض‌های گزارش‌شدهٔ مالک و رگرسیون booking مصرف‌کنندهٔ Sheet و حرکت مشترک.
- تصاویر تازهٔ پیش‌فرض/حالت‌ها در [تصاویر QA](../tests/screens/phase02-review02/)، [عرض‌های مرزی](../tests/screens/refresh-01-02/)، [منابع بازتولیدشده](../tests/screens/design-reference/) و [زیرساخت پایه](../tests/screens/foundation/) هستند. تصاویر خروجی QA در Git نادیده گرفته می‌شوند.
- ارزیابی کارایی این دور محدود به نوع property، زمان‌بندی اندازه‌گیری‌شدهٔ مرورگر، نبود حلقهٔ JS فریم‌به‌فریم و رفتار offscreen/کاهش حرکت است؛ نمرهٔ FPS/Lighthouse یا آزمون گوشی فیزیکی ادعا نمی‌شود.

## محدودیت و دروازهٔ بعد

کمبود asset/مقصدهای نهایی عمومی، پرسش‌های تجاری قبلی و اختلاف BK-01 در فاز ۳ همچنان طبق اسناد مربوط باز هستند. این کار permission یا مقصد واقعی تازه‌ای تصویب نمی‌کند. پس از تحویل، بازبینی اصلاحات همین دو فاز با مالک است؛ فاز بعدی خودکار آغاز نمی‌شود.
