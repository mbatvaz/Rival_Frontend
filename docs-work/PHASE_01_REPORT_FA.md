# گزارش تحویل فاز اول Rival

تاریخ: ۱۹ آبان ۱۴۰۵ — 2026-11-10، منطقهٔ زمانی تهران

**وضعیت: پیاده‌سازی فاز اول و آزمون‌های آن تمام شده؛ پذیرش مالک هنوز ثبت نشده است. فاز دوم آغاز نشده است.**

## نتیجهٔ قابل بازبینی

زیرساخت رابط استاتیک و سازگار با مهاجرت آینده به Razor آماده است. ساخت فعلی ۷۳ مسیر/حالت را با پیام صریح «این صفحه هنوز پیاده‌سازی نشده است» تولید می‌کند؛ فهرست مرکزی و نسخهٔ معادل `pages.html` نیز آماده‌اند. این خروجی، پیاده‌سازی صفحات رزرو، ورود، مشتری، آرایشگر یا مدیر محسوب نمی‌شود.

برای مشاهده در مرورگر، پوشهٔ `Rival_Codex_Starter` را در VS Code باز کنید و از `Tasks: Run Task` گزینهٔ **Rival: Build + Preview** را اجرا کنید. سپس این آدرس را باز کنید:

`http://localhost:4173/_preview/`

فهرست مرکزی ۷۳ لینک دارد و هر مسیر امکان بازگشت به فهرست را دارد. اجرای محلی به ساخت فایل‌ها وابسته است؛ بازکردن مستقیم HTML با `file://` قرارداد اجرای پروژه نیست. سرورهای آزمون پس از اجرای آزمون‌ها بسته شده‌اند.

## کارهای انجام‌شده

- ابزار ساخت از قالب‌های محدود Nunjucks در `src/Views/` استفاده می‌کند. قالب پایه خنثی و سه partial برای فهرست، ردیف و جای‌نگهدار ساخته شد؛ پوستهٔ محصول متعلق به فاز دوم است.
- ۹ خانوادهٔ توکن از فایل اصلی Design System v2 تولید می‌شود. رنگ‌های ارجاعی به متغیر CSS تبدیل می‌شوند و لایه‌های CSS به ترتیب قرارداد بارگذاری می‌شوند.
- سه وزن معمولی Yekan Bakh، ۷۱ آیکون SVG محلی و دو فایل لوگو آماده شدند. نام‌های سازگار `ri ri-*` با CSS mask و رنگ جاری کار می‌کنند. فونت‌های Expanded و کتابخانه یا CDN جدیدی اضافه نشده‌اند.
- آداپتر `core/api.js` تنها مرز داده است. خواندن از fixture، حالت خالی/خطا، لغو درخواست و خطاهای شبکه/ذخیره‌سازی پوشش داده شده‌اند. نوشتن صرفاً در localStorage، با پاسخ `demo: true` و کلید جداگانه برای هر basePath شبیه‌سازی می‌شود.
- registry قابلیت‌ها را با `data-rv` پیدا می‌کند و loader هر قابلیت مورد نیاز را یک بار بارگذاری می‌کند. مقداردهی تکراری و تلاش دوباره پس از خطا آزموده شد؛ قابلیت محصولی در این فاز ثبت نشده است.
- تبدیل ارقام فارسی، تاریخ جلالی با منطقهٔ تهران و ساعت ۲۴ساعته آماده و آزموده شد.
- مسیر اصلی و انتشار در زیرپوشه از همان تنظیم `basePath` پشتیبانی می‌شوند. متغیر `RIVAL_BASE_PATH` تنها برای اجرای ایزولهٔ آزمون استفاده می‌شود و فایل تنظیم اصلی را تغییر نمی‌دهد.
- سرور پیش‌نمایش فقط فایل استاتیک ارائه می‌کند. redirect انتهای اسلش، HEAD، ۴۰۴، ورودی نامعتبر و رد روش‌های نوشتنی بررسی شده‌اند.
- `.htaccess` خروجی، `index.html` را فایل پیش‌فرض می‌کند و فهرست‌کردن پوشه را غیرفعال می‌کند. فقط JSONهای داده به خروجی کپی می‌شوند؛ README داده و سورس قالب‌ها وارد آن نمی‌شوند.
- نسخه‌های وابستگی در `package-lock.json` تثبیت شدند. نصب و اجرای آزمون‌ها، cache و مرورگر محلی پروژه را به کار می‌گیرند. Taskهای کامل آزمون و آزمون زیرپوشه اضافه شدند.

## فایل‌های مهم تغییرکرده

- ساخت و استخراج: `tools/build-static.mjs`، `tools/lib/{site,format,registry,design-system}.mjs`.
- اجرا و بررسی: `tools/serve-static.mjs`، `tools/lint-structure.mjs`، `tools/run-tests.mjs`، `tools/playwright.mjs`.
- قالب‌ها: `src/Views/Shared/_Layout.njk` و `src/Views/Shared/Preview/`.
- دارایی‌ها: `src/wwwroot/css/`، `src/wwwroot/js/`، `src/wwwroot/icons/` و `src/wwwroot/img/`.
- fixtureها: `src/MockData/foundation/` و قرارداد مستند در `src/MockData/README.md`.
- آزمون‌ها: `tests/{smoke.spec.mjs,a11y/,visual/,runtime/,structure/}`، تنظیمات lint و Playwright.
- پیشرفت و رهگیری: `PROGRESS.md`، `docs/{TRACEABILITY,PAGE_INVENTORY,DISCREPANCIES,OPEN_QUESTIONS}.md`.
- راه‌اندازی: `.vscode/tasks.json`، `package.json`، `package-lock.json`، `README_START_HERE_FA.md` و `.gitignore`.
- اصلاح متادیتای مشتق‌شدهٔ STY-CUS: `src/page-registry.json` و `design-export/MANIFEST.{json,md}`.

هیچ فایل اصلی در `design-export/batches/`، `design-export/design-system-v2/` یا `docs/references/` تغییر نکرده است. نسخهٔ اولیهٔ بسته پیش از پیاده‌سازی در commit محلی `84b21b4` حفظ شده است.

## نتایج واقعی بررسی‌ها

- `npm run build`: موفق؛ ۷۳ جای‌نگهدار، ۲ صفحهٔ فهرست، مجموعاً ۷۵ HTML.
- `npm run lint`: موفق؛ بررسی ساختار، ESLint و Stylelint.
- `npm test`: **۱۹ آزمون موفق** در مسیر اصلی.
- `npm run test:subpath`: **۱۹ آزمون موفق** در `/rival-demo/`؛ پس از آزمون، خروجی مسیر اصلی بازسازی شد.
- مسیرهای هر ۷۳ شناسه، لینک‌های بازگشت، وابستگی‌های HTML/CSS/JS، فونت‌ها و آیکون‌ها بدون لینک مفقود بررسی شدند.
- axe روی فهرست و جای‌نگهدار در عرض‌های ۳۹۰، ۷۶۸ و ۱۲۸۰ هیچ نقض WCAG A/AA گزارش نکرد.
- مسیر کامل رفتن با صفحه‌کلید به محتوا، صفحهٔ اصلی و بازگشت به فهرست موفق بود؛ focus قابل مشاهده است.
- اندازهٔ هدف لینک‌ها حداقل ۴۴×۴۴، نبود سرریز افقی و نبود اسکرول عمودی تو‌در‌تو در چهار عرض ۳۲۰، ۳۹۰، ۷۶۸ و ۱۲۸۰ آزموده شد.
- محتوای خروجی `dist/` شامل ۱۷۸ فایل، حدود ۷۵۹ کیلوبایت است؛ Node، Nunjucks، اسناد و آزمون‌ها جزو payload نیستند. پوشه‌های خالی اسکلت ممکن است وجود داشته باشند.
- `git diff --check`: موفق.

## اصلاحات و موارد باز

- **GAP-15:** عبارت توضیحی Markdown به‌اشتباه وارد مسیر STY-CUS شده بود. مسیر درست `/stylist/customers/` از فهرست رسمی اعمال و آزموده شد.
- خطاهای cache خارج از پوشه و خاتمهٔ سرور آزمون در ویندوز با مسیر cache محلی و مدیریت IPC سرور رفع شدند.
- OQ-01 تا OQ-06 بدون تغییر باقی‌اند؛ هیچ تصمیم تجاری، مالی یا مجوزی در این فاز حدس زده نشد.
- CUS-02 از جریان رزرو ترکیب می‌شود و CUS-07 جایگاه موجودی داخلی است؛ آرت‌بورد مستقل برای آن‌ها ساخته نشده است. کمبودهای طراحی و اسکرین‌شات‌های قبلی برای فازهای مربوط باقی‌اند.
- هیچ پرداخت، رزرو، احراز هویت یا انتشار خارجی انجام نشده است. آماده‌بودن payload استاتیک به معنی آزمودن آن روی cPanel واقعی نیست.

## دروازهٔ بعدی

مالک باید نتیجهٔ فاز اول را بازبینی و پذیرش آن را اعلام کند. پس از آن فاز دوم می‌تواند به‌طور صریح محول شود. فاز دوم پوستهٔ مشترک، ناوبری نقش‌ها، صفحات عمومی و ورود را می‌سازد؛ briefهای دسکتاپ آن پیش از پیاده‌سازی برای تأیید ارائه خواهند شد.
