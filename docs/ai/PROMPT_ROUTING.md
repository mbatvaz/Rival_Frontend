# Prompt routing and verification

[Root instructions](../../AGENTS.md) define the four levels. Select by impact, including responsive, accessibility and shared consumers. A one-line change to a shared selector can be level 3. An annotation supplies evidence about a target, while the owner's request supplies the scope.

| Level | Start with | Expand when | Verify |
| --- | --- | --- | --- |
| 1 Element | Known file and rule or the annotation lookup result. Read the matching block, neighboring override and relevant token. | Ownership is ambiguous, or another view, state, keyboard interaction or semantic rule changes. | Scoped lint and the affected rendered state at the reported width and one affected boundary if relevant. |
| 2 Page | Template, affected partials, fixture, feature and styles for the state. Read the relevant design excerpt, page decision and existing test. | A shared primitive, navigation, data contract or permission is affected. | Changed states, affected breakpoints, relevant interactions and accessibility. |
| 3 Shared | Canonical owner, affected consumers, relevant decisions and test references. Use the [graph](PROJECT_INDEX.md) for unknown dependencies and confirm real consumers. | The work changes architectural boundaries, owner-approved composition or phase requirements. | Recheck representative affected consumers and all affected contracts, including root/subpath for shared URLs. Use focused tooling checks for infrastructure. |
| 4 Phase | Current [plan](../PHASE_PLAN.md), [progress](../../PROGRESS.md), phase package and exact design states. Load each slice's dependencies as needed. | Apply the owner gate and escalate unresolved decisions to the owner. | Complete applicable [QA gates](QA_CHECKLIST.md), traceability and acceptance evidence. Report browser, accessibility, keyboard, reduced motion, source comparisons and supported widths. |

Use the [skill registry](SKILL_REGISTRY.md) to select applicable guidance. Visual QA owns the shared browser checks. Specialists add evidence without duplicating checks for an unchanged revision and scope. For a new or redesigned screen, follow the full relevant design comparison and browser checklist. For focused fixes, keep the evidence proportional to the impact and report unverified areas. This routing does not change acceptance gates.

## Local QA for all phases

Choose verification by the actual diff. Use `npm run qa:affected -- --file <path>` for behavioral or structural changes. Repeat `--file` for every file in the task when the worktree contains other changes. Without explicit files, the command uses the worktree diff against HEAD and untracked files. Use `--plan` when the selection needs inspection. A normal run selects and runs tests without a separate test inventory.

- For a reviewed appearance-only declaration change in a component or page stylesheet, use `npm run qa:affected -- --cosmetic --file <stylesheet>`, including in shared styles. It runs scoped Stylelint and one build. When rendering or fit depends on the change, add `--url`, `--selector` and the affected `--width` values to check that state in Chromium within the same build. Use normal affected QA for changes to layout structure, visibility, focus, interactions, asset URLs or global styles.
- For a verified local CSS edit, pass `--element --url '<preview URL>' --selector '<target>'` and repeat `--width` for affected breakpoints. In this case, when the stylesheet resolves to one page and the route matches, the probe replaces the suite. It checks runtime readiness, element visibility, dimensions, overflow and browser errors. Add `--axe` for accessibility and `--screenshot` for visual comparison. Check the rendered result against the request.
- The command maps files to consumers and deduplicates Playwright specs in a single run per base path. Shared selection uses [audited coverage](../../tools/lib/qa-coverage.mjs) where available and otherwise uses linked tests. Default rendered selectors are evidence of possible ownership. If a dynamic consumer or state is known outside that evidence, include its test file with `--file` or expand to `--full`.
- Global inputs, unresolved ownership and absent mapped coverage surface the reason and require explicit `--full` to launch the full suites. Resolve the scope first when practical. Template, script, data and asset changes are checked at both base paths. Use `--subpath` for URL-sensitive CSS changes. When both paths run, the subpath runs first and the root build restores the preview.
- Use `--full` for complete repository lint and Playwright in both paths during phase acceptance. Complete any separate phase evidence checks. The registry and dependency graph drive this workflow across phases, including routes added in later phases.

## Browser annotations

- The Desktop comment supplies the page URL, state, selector and sometimes a screenshot. Reuse a verified source address if available. Otherwise run `node tools/resolve-annotation.mjs '<URL>' '<selector>'`. Single quote both inputs in PowerShell and double any literal single quote inside them. Supply the full selector once.
- When the [project hook](../../.codex/hooks.json) is trusted in Codex Desktop, it attaches the source addresses for up to four distinct annotation targets before the first model call. It reads the submitted annotation metadata locally and emits only source addresses and page IDs. Ordinary prompts produce no hook context. If Codex has not loaded or trusted the hook, the command above provides the same lookup.
- The resolver finds the page in the current registry and reads the reachable literal Nunjucks imports/includes and CSS imported by the app. It returns the page ID, template and at most four files per category with line numbers. It reports remaining candidate counts. It recognizes root routes, the configured base path and `/rival-demo/`. For a preview using a different base path, set `RIVAL_BASE_PATH` for that command.
- Candidate lines help locate source. Conditional templates, ancestor matches and CSS overrides need confirmation. If there is no exact hook, use a distinctive parent or inspect the relevant subtree. JavaScript-created markup, dynamic includes and external routes can require [project navigation](PROJECT_INDEX.md) or the smallest relevant browser observation.
- Retain the URL state when validating. Use the attached screenshot when sufficient, obtain a focused browser snapshot when needed and keep comparison evidence on disk.

## Short tool output and handoff

- Batch independent reads and return only names, matching regions or a short summary. For project map navigation start with `npm run map:query -- PAGE-ID --compact` and expand when edge evidence is needed. Combine checks that share the same build. The managed Playwright runner builds before testing, and subpath mode restores the root build.
- For agent validation of browser tests, use `npm test -- --agent <affected test files or filter>`. A single Chromium navigation checks preview access before the suite. The command returns a summary and the local full log. If access fails, diagnose that cause before retrying. Use the ordinary runner for verbose interactive output.
- For independent work in a new chat, hand off the assigned scope, page ID/state/source addresses, effective decisions, valid checks and open gaps. Link evidence and omit historical tool outputs.
- For benchmarks, start each variant with equivalent fresh history, attachments, model, effort and checks. Measure each independently. Record elapsed time, calls, total and cached input and output separately. Local command output measures lookup context only. Codex manages the conversation prefix. Use attributable usage data before reporting quota savings.

## Engineering details by scope

- UI work follows the [implementation contract](DESIGN_IMPLEMENTATION_CONTRACT.md), [component ownership](../COMPONENT_REUSE_MATRIX.md), [responsive contract](RESPONSIVE_DESIGN_CONTRACT.md) and [motion specification](MOTION_SPEC.md). Use v2 tokens, Yekan Bakh 300/400/600, local Lucide icons and `rv-*`/data-rv conventions. Preserve localized RTL semantics, logical CSS, >=44px targets and native CSS layers. Keep `app.css` import-only and follow the repository CSS/JS size targets. Confirm exact evidence through the [design manifest](../../design-export/MANIFEST.json) and document conflicts in [design conflicts](DESIGN_SOURCE_CONFLICTS.md).
- Bottom sheets are the default. DEC-037 covers centered desktop PortfolioViewer. Mobile BK-REC01 has the approved nested scrolling exception. Follow the motion contract for interruption, fallback and reduced motion, and reserve media dimensions.
- Use the [MVC guide](../ASP_NET_MVC_MIGRATION_MAP.md) only during Phase 09 or explicit MVC review. Review approvals follow the [local storage and tooling contract](../../preview-review/README.md). StatePage ownership is Phase 03 and finance ownership is Phase 06, with Phase 08 extensions.
- Use the [Git workflow](../GIT_WORKFLOW.md) for branching and publication. Update [progress](../../PROGRESS.md), [inventory](../PAGE_INVENTORY.md), [traceability](../TRACEABILITY.md), [discrepancies](../DISCREPANCIES.md) and [open questions](../OPEN_QUESTIONS.md) where the change affects them.
