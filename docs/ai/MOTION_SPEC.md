# Motion contract and current audit

Authority: [contract](../RIVAL_PROJECT_CONTRACT.md), [MotionSpecimens](../../design-export/design-system-v2/components/MotionSpecimens/README.md), [tokens](../../design-export/design-system-v2/tokens/tokens.json).

Durations: fast 140ms, base 240ms, slow 380ms, deliberate 700ms. Easings: ease-standard, ease-exit, ease-spring. Use existing tokens for new motion. Motion explains change, never blocks a task or conveys meaning alone.

For every animation complete the [record](templates/motion-spec.md): purpose/source, trigger, initial/final state, duration/delay/easing/stagger, interruption/reversal/cancellation, navigation cleanup, reduced motion, browser fallback, performance budget and evidence. Include keyboard activation and rapid repeated interaction.

Prefer CSS for declarative effects and use the shared [Motion adapter](../../src/wwwroot/js/components/motion.js) for scripted effects and cancellation. View Transitions need ordinary-navigation fallback. Prefer transform/opacity and batch layout reads before writes. [Approved dependencies and byte measurements](DEPENDENCY_POLICY.md).

## Current implementation

- **Owner-directed entries, 2026-11-25.** [Route entries](../../src/wwwroot/js/components/route-entries.js) use the existing Motion adapter. Type 1 fades from a short physical-left offset at every width. Type 2 reveals the notice from its right edge without resizing its layout. The owner-directed scenes run at 60% speed. Cards start 116.5 ms apart over 400 ms, except the 633 ms portfolio zoom. Dashboard groups run in parallel. Past appointments finish each month's row sequence before opening the next month. Detail hero media waits for its information panel, then reveals from bottom to top. Rules begin as sections intersect the viewport. Requested package cards rise, and fixed action cards slide up.
- **Replay and interruption.** Changing the appointment/request tab starts a new sequence. The portfolio waits for the outgoing zoom/fade, then applies the latest filter and starts a new entry. Opening a popup cancels entry in the background and closing it does not restart entry. Mobile PortfolioViewer and the requested sheets travel from and back to the bottom. Centered desktop PortfolioViewer and the More navigation drawer retain their own motions. The booking Embla rail and PhotoSwipe keep ownership of their transforms. Auth stage changes fold the form up and down, with a left-to-right OTP bounce. Recurring edits batch geometry reads around the DOM update, move existing rows into position and then reveal new rows. Removed rows exit before the remaining rows close the gap. Reduced motion, focus interruption and missing Web Animations leave the final state usable. Use Gesture dismisses bottom sheets with a downward drag on the header or grip, including the sticky recurring editor handle. The exit continues from the dragged position. More dismisses with a leftward drag. Opening uses the existing controls. Short gestures settle without closing.
- **First render and loading.** Outside the public home, placeholders stay through feature initialization and font settlement. The design-system [skeleton](../../src/wwwroot/css/03-components/skeleton.css) preserves the 1.4-second shimmer from [the export](../../design-export/design-system-v2/css/rival.css) and becomes static with reduced motion. [Card media](../../src/wwwroot/js/components/card-media.js) keeps image-dependent cards in their placeholders through decoding and releases them on errors. A late individual image can finish independently of its neighbors. The public home uses its 800 ms typography fallback without the skeleton.
- **Checkout and OTP.** Checkout keeps the loading surfaces in place until the selected images decode or fail and starts the existing entry sequence before releasing the skeleton. The text moves independently of the avatar so its mobile absolute positioning uses the same containing block throughout. The receipt surface allows its contents to paint outside the moving regions while the ticket still owns image clipping. A rejected OTP moves the shared row once with transform keyframes and leaves the error, expiry and lock messages to the verification flow. The existing reduced-motion guard disables the shake.
- **Final confirmation.** Activate the existing confirmation or submit button with a click, tap, Enter or Space. Confirmation sheets, disabled states, payment expiry and write rules remain part of their existing flows.
