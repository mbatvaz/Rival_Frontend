# Design implementation procedure

Apply within the [canonical architecture](../RIVAL_PROJECT_CONTRACT.md). Exact page evidence refines appearance; it cannot silently authorize forbidden frameworks or business permissions.

1. Identify Page ID, affected states and accepted dependencies. Find the [implemented pattern](../COMPONENT_REUSE_MATRIX.md#implemented-reuse) before drafting structure or styles.
2. Use [compact routing](PROMPT_ROUTING.md) to find the exact design state and confirmed product decision. Render exact HTML where needed and record missing evidence.
3. For a new page record source, state, copy, assets and component references in the [page spec](templates/page-spec.md). For a targeted edit record just the affected evidence and checks.
4. Follow the [responsive procedure](RESPONSIVE_DESIGN_CONTRACT.md). New work in phases 05–09 has one mobile composition with wider adaptation. Keep accepted desktop briefs for maintenance of existing layouts.
5. Implement rv-* partials, native layered CSS and lazy modules, preserving basePath/mock boundaries. Use existing tokens; log unmatched geometry rather than create a parallel vocabulary.
6. Run the affected checks once. For new or changed compositions compare fresh captures to exact states with at least five concrete observations. Reuse existing comparisons where the composition is unchanged.
7. Fix blockers/major mismatches; record deviations with source, reason and acceptance status. Pending is not accepted. Update tracking docs and stop at phase gate.

Use supplied assets/approved Persian content. [Public provenance](../../docs-work/PHASE_02_ASSET_MAP.json) maps runtime photos to export originals. Missing final destinations remain OQ-08; fixtures may retain approved development samples.
