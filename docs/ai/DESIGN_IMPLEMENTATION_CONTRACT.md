# Design implementation procedure

Apply within the [canonical architecture](../RIVAL_PROJECT_CONTRACT.md). Exact page evidence refines appearance; it cannot silently authorize forbidden frameworks or business permissions.

1. Identify phase, Page ID, route/context and states; verify accepted dependencies. Read exact handoff and latest confirmed feedback.
2. Locate all source candidates in the [map](DESIGN_SOURCE_MAP.md). Inspect actual content/dimensions/state before selecting evidence. Null selectors/missing screenshots are gaps. Render exact HTML where needed; never invent selectors.
3. Complete a [page spec](templates/page-spec.md) with per-state source, copy, assets and component/token references. Reuse existing implementations; log conflicts before editing.
4. Present scoped files/checks; distinguish mobile invariants from adaptation. Follow [responsive procedure](RESPONSIVE_DESIGN_CONTRACT.md) and desktop review gate.
5. Implement rv-* partials, native layered CSS and lazy modules, preserving basePath/mock boundaries. Use existing tokens; log unmatched geometry rather than create a parallel vocabulary.
6. Build/lint; test relevant routes/states and shared regressions at root/subpath, then browser QA. Compare fresh captures to exact states with >=5 observations spanning copy/layout/type/palette/spacing/container/assets/icons/motion.
7. Fix blockers/major mismatches; record deviations with source, reason and acceptance status. Pending is not accepted. Update tracking docs and stop at phase gate.

Use supplied assets/approved Persian content. [Public provenance](../../docs-work/PHASE_02_ASSET_MAP.json) maps runtime photos to export originals. Missing final destinations remain OQ-08; fixtures may retain approved development samples.
